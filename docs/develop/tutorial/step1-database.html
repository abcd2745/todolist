📖 理论说明

🐳 Docker容器化

核心概念：使用Docker容器运行PostgreSQL数据库，确保环境一致性和隔离性。

  • 容器：轻量级的独立可执行软件包，包含运行所需的所有内容
  • 镜像：只读模板，用于创建容器（postgres:15-alpine）
  • Volume：持久化存储，数据不会随容器删除而丢失

🔌 端口映射

为什么固定端口？

  • 所有Agent共享同一个数据库实例
  • 端口固定为5432，简化配置
  • 通过Schema隔离数据，而非端口隔离

💡 关键点

与传统方案不同，我们不需要为每个Agent分配不同端口。Schema隔离已经解决了数据冲突问题。

💾 Volume持久化

数据持久化原理：

  • postgres_data：Docker管理的命名卷
  • 存储数据库文件、Schema、表数据
  • 容器重启或重建，数据不会丢失

🔧 实际操作

1. 查看docker-compose.yml配置

version: '3.8' services: postgres: image: postgres:15-alpine container_name: todolist-db environment: POSTGRES_USER: dev POSTGRES_PASSWORD: dev_password POSTGRES_DB: todolist ports: - "5432:5432" volumes: - postgres_data:/var/lib/postgresql/data volumes: postgres_data:

📋 配置详解

  • image: postgres:15-alpine
    使用PostgreSQL 15的Alpine版本（轻量级）
  • environment
    设置数据库用户名、密码、数据库名
  • ports: "5432:5432"
    主机端口:容器端口映射
  • volumes: postgres_data
    命名卷，持久化存储

2. 启动数据库容器

docker-compose up -d

参数说明：

  • up - 创建并启动容器
  • -d - 后台运行（detached mode）
[+] Running 2/2 ✔ Network todolist_default Created ✔ Container todolist-db Started

3. 验证容器状态

docker ps | grep todolist-db
CONTAINER ID IMAGE COMMAND STATUS PORTS NAMES abc123def456 postgres:15-alpine "docker-entrypoint.s…" Up 10 seconds 0.0.0.0:5432->5432/tcp todolist-db

4. 测试数据库连接

docker exec -it todolist-db psql -U dev -d todolist -c "SELECT version();"
version ----------------------------------------------------------------------- PostgreSQL 15.2 on x86_64-pc-linux-musl, compiled by gcc (Alpine 12.2.1_git20220924-r7) 12.2.1 20220924, 64-bit (1 row)

❓ 常见问题

Q: 端口5432被占用怎么办？

A: 可以修改docker-compose.yml中的端口映射：

ports: - "5433:5432" # 使用主机端口5433

Q: 如何停止数据库？

docker-compose down # 停止并删除容器 docker-compose down -v # 停止并删除容器和volume

Q: 如何查看日志？

docker-compose logs postgres docker-compose logs -f postgres # 实时查看
