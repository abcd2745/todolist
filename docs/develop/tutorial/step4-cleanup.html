📖 理论说明

🗑️ DROP SCHEMA原理

删除Schema的核心命令：

-- 删除Schema（必须为空） DROP SCHEMA agent_1; -- 删除Schema及其所有对象（CASCADE） DROP SCHEMA agent_1 CASCADE;

⚠️ CASCADE的作用

CASCADE会自动删除Schema中的所有对象（表、视图、函数等），无需手动删除每个对象。

注意：这是一个不可逆操作，数据将永久删除。

⚡ 为什么清理很重要？

  • 释放资源：删除不再使用的表和数据，节省存储空间
  • 避免干扰：防止旧数据干扰新的测试
  • 保持整洁：维护干净的数据库环境
  • 团队协作：清理个人环境，不影响其他Agent

🔄 Schema重建

清理后如何重新创建？

删除Schema后，可以立即重新创建，实现环境重置：

-- 清理 DROP SCHEMA agent_1 CASCADE; -- 重建 CREATE SCHEMA agent_1; GRANT ALL PRIVILEGES ON SCHEMA agent_1 TO dev;

自动化清理脚本示例

#!/bin/bash # scripts/cleanup-old-schemas.sh # 清理超过7天未使用的Schema THRESHOLD_DAYS=7 unused_schemas=$(docker exec -i todolist-db psql -U dev -d todolist -t -c " SELECT schema_name FROM information_schema.schemata WHERE schema_name LIKE 'agent_%' AND schema_name NOT IN ( SELECT DISTINCT schemaname FROM pg_stat_user_tables WHERE last_seq_scan > NOW() - INTERVAL '$THRESHOLD_DAYS days' ); ") for schema in $unused_schemas; do echo "清理未使用Schema: $schema" docker exec -i todolist-db psql -U dev -d todolist -c "DROP SCHEMA IF EXISTS $schema CASCADE;" done

❓ 常见问题

Q: 清理Schema会影响其他Agent吗？

A: 不会。每个Schema完全独立，清理agent_1不会影响agent_2或其他任何Schema。

Q: 如何恢复误删的Schema？

A: Schema删除后无法直接恢复，只能：

  1. 从备份恢复（如果有备份）
  2. 重新创建Schema并重新导入数据

强烈建议：清理前先备份数据！

Q: 如何备份Schema？

# 备份单个Schema docker exec todolist-db pg_dump -U dev -n agent_1 todolist > backup_agent1.sql # 恢复 cat backup_agent1.sql | docker exec -i todolist-db psql -U dev -d todolist

Q: DROP SCHEMA CASCADE安全吗？

A: CASCADE会级联删除所有依赖对象，在清理场景下是安全的，因为我们要删除的就是整个Schema及其所有内容。

注意：生产环境慎用CASCADE，建议先检查依赖关系。
