## 1. 产品概述

### 1.1 产品定位

一款**数据驱动的自我改进**游戏化待办事项系统，基于艾森豪威尔四象限原则，帮助用户：
- 有效管理日常任务与长期目标
- 通过游戏化机制激发完成任务的热情
- 通过数据分析理解自己的行为模式
- 实现可持续的自我改进

### 1.2 产品愿景

> 成为用户"理解我、帮助我、不评判我"的成长伙伴，而非冷冰冰的效率监工。

### 1.3 核心价值主张

| 传统待办应用 | 本产品 |
|--------------|--------|
| 任务列表 + 打勾 | 四象限优先级 + 游戏化成长 |
| 社交竞争/排行榜 | 数据驱动的自我改进 |
| 冷冰冰的进度百分比 | 温暖的"冒险之旅"叙事 |
| 评判性文案 ("你落后了") | 理解性文案 ("欢迎回来") |
| 静态任务管理 | AI 辅助长任务拆分与学习规划 |

## 3. 核心设计理念

### 3.1 产品核心原则

经过两次多角色讨论会确认，以下原则为产品设计的"宪法"：

```
┌─────────────────────────────────────────────────────────┐
│  核心设计原则 (宪法级)                                   │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  1. 理解我、帮助我、不评判我                            │
│     → 所有文案、交互、反馈必须通过此检查               │
│                                                         │
│  2. 数据服务于理解，而非焦虑                            │
│     → 数据展示强调"发现"而非"问题"                     │
│                                                         │
│  3. 提供选择权                                          │
│     → 游戏/专业模式切换、极简模式可选                  │
│                                                         │
│  4. 洞察 + 反思 = 改变                                  │
│     → 每个洞察配反思入口，促进用户自我觉察             │
│                                                         │
│  5. 小步快跑                                            │
│     → 实验周期 1-2 周，降低尝试门槛                       │
│                                                         │
│  6. 避免分析瘫痪                                        │
│     → 默认只展示 3-5 个核心指标                          │
│                                                         │
│  7. 友好断签机制                                        │
│     → 复活机制、休假模式、断签后积极文案               │
│                                                         │
│  8. AI 是建议者，不是命令者                             │
│     → 透明的决策逻辑，用户有最终编辑权                 │
│                                                         │
│  9. 计划是为用户服务的，不是束缚用户的                  │
│     → 动态重规划，允许弹性调整                         │
│                                                         │
│  10. 强调"已走了多远"而非"还有多远"                     │
│     → 进度展示强调已完成，而非剩余                     │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 3.2 文案语气规范

| 场景 | ❌ 避免 | ✅ 推荐 |
|------|--------|--------|
| 连击断裂 | "你的连击已中断" | "欢迎回来！新连击从 1 开始" |
| 进度落后 | "你落后了 15%" | "这周确实很忙，我帮你调整计划" |
| 任务逾期 | "你逾期了 3 个任务" | "有 3 个任务需要重新安排时间" |
| 四象限失衡 | "第一象限占比过高" | "近期紧急任务较多，注意保护成长时间" |
| 数据洞察 | "你的效率低于基准" | "你今天在 XX 时段完成了 3 个任务" |

### 4.2 任务管理模块

#### FR-001: 四象限任务分类

| 属性 | 描述 |
|------|------|
| ID | FR-001 |
| 名称 | 四象限任务分类 |
| 优先级 | P0 |
| 描述 | 支持将任务分类到四个象限：紧急且重要 (主线)、重要不紧急 (成长)、紧急不重要 (委托)、不紧急不重要 (休闲) |
| 验收标准 | <ul><li>新建任务时通过两个问题自动分类</li><li>支持手动调整象限</li><li>主界面清晰展示四象限分布</li></ul> |

**象限定义:**
| 象限 | 名称 | 游戏化命名 | 说明 |
|------|------|------------|------|
| Q1 | 紧急且重要 | 主线任务 | 必须攻克的核心任务 |
| Q2 | 重要不紧急 | 成长区域 | 长期目标、学习提升 |
| Q3 | 紧急不重要 | 村庄委托 | 快速完成的日常事务 |
| Q4 | 不紧急不重要 | 休闲时光 | 放松、娱乐类任务 |

---

#### FR-002: 长任务管理

| 属性 | 描述 |
|------|------|
| ID | FR-002 |
| 名称 | 长任务管理 |
| 优先级 | P0 |
| 描述 | 支持创建和管理持续 2 周以上的长期目标，如考试准备、技能学习、项目开发 |
| 验收标准 | <ul><li>自动识别长任务 (>2 周)</li><li>支持 AI 辅助拆分</li><li>地图式进度可视化</li><li>里程碑系统</li></ul> |

**长任务特征:**
- 持续时间 > 2 周
- 需要多个步骤完成
- 有明确的最终目标
- 典型场景：考试准备、技能学习、项目开发、习惯养成

---

#### FR-003: AI 任务拆分

| 属性 | 描述 |
|------|------|
| ID | FR-003 |
| 名称 | AI 任务拆分 (Aurora) |
| 优先级 | P0 |
| 描述 | AI 辅助将长目标拆分为可执行的子任务，生成学习路径 |
| 验收标准 | <ul><li>5 分钟内完成初始设置</li><li>生成可编辑的子任务列表</li><li>解释拆分逻辑 (依赖关系、难度曲线)</li><li>支持动态重规划</li></ul> |

**AI 拆分流程:**
1. 目标定义 (名称、截止日期、每日可用时间、现有基础)
2. 资源导入 (教材目录/课程大纲/学习目标)
3. 计划生成 (AI 生成学习路径图)
4. 用户编辑 (可拖拽调整顺序)
5. 开始执行 (每日推送任务)

#### FR-004: 动态重规划

| 属性 | 描述 |
|------|------|
| ID | FR-004 |
| 名称 | 动态重规划 |
| 优先级 | P0 |
| 描述 | 当用户进度偏离时，AI 主动提供调整方案，而非评判 |
| 验收标准 | <ul><li>检测进度偏差 (连续 3 天未完成/主动反馈)</li><li>询问原因 (工作忙/任务难/其他)</li><li>提供 2-3 个调整方案</li><li>用户有最终选择权</li></ul> |

**重规划方案示例:**
- 方案 A: 延长本周目标 (不影响最终截止)
- 方案 B: 降低本周难度 (后续增加时间)
- 方案 C: 保持原计划 (加油完成)

- LV 1-5: 新手冒险者 → 时间学徒
- LV 6-10: 时间管理者 → 成就收集者
- LV 11-15: 四象限骑士 → 效率传说
- LV 16-20: 时间守护者 → 四象限大师

CREATE TABLE user_behavior_logs (

CREATE TABLE daily_metrics (

CREATE TABLE user_insights (

## 7. 行为设计需求

### 7.1 习惯回路设计

**线索 (Cue):**
- 时间线索：每天 9 点推送"今日冒险指南"
- 情境线索：打开应用自动展示"现在适合做什么"
- 情绪线索：用户选择"我现在感觉___"推荐任务

**例行 (Routine):**
- 简化流程：点击任务 → 确认完成 → 获得奖励
- 仪式感：完成任务前有简短动画 (可跳过)
- 专注模式：开启后 25 分钟内不能切换任务 (番茄钟)

**奖励 (Reward):**
- 固定奖励：XP、完成动画、进度增长
- 可变奖励：幸运暴击 (10% 概率 2 倍 XP)、神秘宝箱
- 成长奖励：属性点增长、成就解锁

### 7.2 文案语气检查清单

所有用户可见文案必须通过以下检查：

- [ ] 是否使用评判性语言？("你应该"、"你错了")
- [ ] 是否制造焦虑？("落后"、"逾期"、"警告")
- [ ] 是否提供可操作建议？
- [ ] 是否强调"发现"而非"问题"？
- [ ] 是否尊重用户选择权？

### 7.3 峰值 - 终值设计

**峰值时刻:**
- 完成任务瞬间：粒子动画 + 音效 + XP 跳动
- 升级时刻：全屏庆祝动画 + 新称号解锁
- 里程碑：7 天/30 天/100 天成就解锁

**结束时刻:**
- 每日结束："今日冒险总结" - 强调成就
- 每周结束："冒险周报" - 强调成长
- 任务取消："归档到回忆录" - 正面 framing

## 9. 风险与缓解

### 9.1 产品风险

| 风险 | 可能性 | 影响 | 缓解措施 |
|------|--------|------|----------|
| 游戏化新鲜感消退 | 高 | 高 | 提供游戏/专业模式切换，核心功能本身有价值 |
| 数据过载导致焦虑 | 中 | 高 | 默认只展示 3-5 个核心指标，高级分析需主动展开 |
| AI 拆分不靠谱 | 中 | 中 | AI 是建议者，用户可编辑，透明的决策逻辑 |
| 用户依赖 AI 失去自主性 | 低 | 中 | AI 解释"为什么这样安排"，培养元认知能力 |

### 9.2 技术风险

| 风险 | 可能性 | 影响 | 缓解措施 |
|------|--------|------|----------|
| AI 模型成本高 | 中 | 中 | 使用轻量级模型 + 缓存，优化调用频率 |
| 数据分析性能 | 低 | 中 | 定时预计算聚合表，实时查询缓存 |
| 离线同步复杂 | 中 | 低 | 使用成熟的离线优先框架 |

### 9.3 行为设计风险

| 风险 | 可能性 | 影响 | 缓解措施 |
|------|--------|------|----------|
| 外在奖励侵蚀内在动机 | 中 | 高 | XP 获取"润物细无声"，强调成长叙事 |
| 完美主义陷阱 | 中 | 高 | 友好断签机制，弹性进度，自我同情文案 |
| 分析瘫痪 | 低 | 中 | 限制每日数据查看频率，强调行动 |
